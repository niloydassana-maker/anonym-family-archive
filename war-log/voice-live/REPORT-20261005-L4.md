## L4 and XTTS A/B

Same clinic paragraph rendered by `/say`; PCM is 24 kHz mono. RTF is generation seconds divided by audio seconds (lower is faster).

| Variant | Generation | Audio | RTF | Result |
|---|---:|---:|---:|---|
| fp32, speed 1.0, pauses kept | 4.427 s | 8.811 s | 0.502 | Chosen default; full pauses preserved. |
| autocast, speed 1.0 | 5.817 s | 9.103 s | 0.639 | Slower than native fp32 on this L4. |
| fp32, speed 1.35 | 4.355 s | 6.221 s | 0.700 | Shorter/faster speech; keep as comparison sample, not default. |
| fp32, speed 1.0, pause collapse on | 4.482 s | 6.718 s | 0.667 | Removes about 23.8% of duration; left disabled because it can flatten phrasing. |
| fp32, speed 1.0, postprocess off | 4.476 s | 8.864 s | 0.505 | Nearly same duration as edge-trimmed audio; edge trim is not the main prosody issue. |

Production `/turn` uses XTTS `inference_stream()` with cached speaker latents. Warm streamed TTS RTF was about 0.65–0.70 on the L4. FP32 beat autocast in the same-text test, so the L4 keeps XTTS weights in fp32 and uses Whisper large-v3-turbo in CUDA float16. It is not beneficial to force half precision for XTTS on this measured path.

An XTTS-to-Whisper round-trip heard the main Hindi sentence and clinic hours, but recognized the clinic name imperfectly (`लोटी का पुरोहित`) and made minor phonetic errors. This indicates understandable content, not proof of natural-sounding prosody. ### Architecture and licensing decision record

- Current TTS is an NVIDIA-hosted API call; Magpie is not deployed on the Modal L4. Moving it onto L4 would require a self-hosted Speech NIM/NeMo runtime and serving endpoint, but the phone's PCM interface can remain unchanged. NVIDIA lists about 12.58 GiB GPU memory for the default batch-8 Magpie profile; co-residency with Whisper on the 24 GB L4 needs an actual memory and concurrency test.
- NVIDIA Developer Program access to hosted NIM endpoints is for prototyping. NVIDIA's published FAQ says production use requires NVIDIA AI Enterprise. Treat the API as prototype-only until production entitlement and data-handling terms are confirmed.

### Model selection criteria for a faster NVIDIA-hosted LLM

- Nemotron 3 Ultra was chosen for Hindi-capable provider inference and instruction following, not because it was expected to be fastest. Its hosted latency is now the leading target for A/B testing.
- A replacement must explicitly support Hindi in NVIDIA's model documentation, follow the clinic's concise response constraints, stream from NVIDIA-hosted inference, and pass a fixed Hindi clinic-answer/recognition set. Compare p50/p95 time-to-first-token, first spoken PCM, full turn, answer correctness, and Baba's listening judgment. Do not infer latency from parameter count alone.
- NVIDIA's Nemotron Nano 30B and Nemotron 3.5 Lightning published supported-language lists omit Hindi, so they are not safe assumed drop-ins. NVIDIA's hosted Llama 3.3 70B documentation does list Hindi and is a reasonable candidate for a controlled A/B, but it has not been tested or switched. Sources: [Nemotron Ultra API/model documentation](https://docs.api.nvidia.com/nim/re/reference/nvidia-nemotron-3-ultra-550b-a55b), [Nemotron Nano 30B language list](https://docs.api.nvidia.com/nim/re/reference/nvidia-nemotron-3-nano-30b-a3b), [Nemotron 3.5 Lightning language list](https://docs.api.nvidia.com/nim/re/reference/nvidia-nemotron-3-5-lightning-30b-a3b), [NVIDIA-hosted Llama 3.3 70B documentation](https://docs.api.nvidia.com/nim/reference/meta-llama-3_3-70b-instruct).
